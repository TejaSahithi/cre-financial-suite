# Release 7 GA Readiness Report

Status: Not ready for GA. Release 7 adds the controls needed to make a supported go/no-go decision; it does not declare production-wide strict activation.

Architecture summary:
- Release 6 remains the semantic architecture.
- Release 7 adds benchmark, scoring, idempotency, frontend isolation, load-test definitions, security validation, and operational runbooks.

Corpus composition:
- CI corpus: synthetic, cached-provider fixtures permitted for repository use.
- Staging-private corpus: 50 secure family references in `benchmarks/corpus-manifest.json` with no lease text committed.
- Target production-representative corpus remains 50+ families, 100-200 documents, and 3000-8000 pages.

Benchmark results:
- Run `npm run benchmark:regression` to generate `benchmarks/reports/latest/benchmark-report.json`.
- CI fixtures are deterministic and cost-free.
- Live Azure/OpenAI benchmark execution remains a staging-only activity.

Critical-field accuracy:
- Enforced by approval-critical and financial metric gates in the benchmark runner.

Semantic accuracy:
- Definitions, cross references, amendment effects, family linking, and family-effective fields are scored separately.

Amendment precedence:
- Amendment-effect and family-effective thresholds are separate so field accuracy cannot hide precedence failures.

Performance and load:
- Load-test definitions exist for review payload reads, semantic search, reviewer actions, and ingestion.
- Production percentiles require k6 or equivalent execution in staging.

Security:
- Tenant isolation is statically checked and must be manually verified after local/staging migration.

Accessibility:
- Semantic panels are optional and isolated. Manual keyboard and screen-reader review remains required for GA.

Known limitations:
- CI corpus is intentionally small and synthetic.
- Staging-private fixtures are references and require secure corpus storage.
- Live-provider metrics are not generated by pull-request checks.

Open risks:
- Provider latency and rate limits.
- Poor scan quality on unrepresented lease forms.
- Amendment chains with same-day conflicting effects.
- Reviewer workflow drift from benchmark adjudication rules.

Rollback readiness:
- Rollback is configuration-only: v2 to v1, strict to hybrid, hybrid to shadow, semantic search off, semantic approval gating off.
- Semantic records do not need deletion for rollback.

Operational ownership:
- Engineering owns pipeline failures and rollback.
- Product/legal operations own adjudication and go/no-go approval.
- Security owns isolation and sensitive logging review.

Go/no-go decision:
- No-go until staging-private benchmark, security validation, load test, rollback drill, and accessibility review are complete.
